# DK Quality Construction: website

This is the production website for **DK Quality Construction LLC**, a deck builder and remodeling contractor in Monroe, Michigan. It serves Monroe County, MI and Lucas County, OH.

- **Stack:** a static site generated by one zero-dependency Node script (`build.mjs`). There is no framework and no runtime npm packages.
- **Hosting:** Netlify (static hosting, Netlify Forms, headers and redirects in `netlify.toml`).
- **Reports:**
  - QA and launch report: [`DK-Quality-Construction-QA-Report.md`](DK-Quality-Construction-QA-Report.md)
  - Research and fact sources: [`docs/research.md`](docs/research.md)
  - Asset licensing: [`docs/asset-inventory.md`](docs/asset-inventory.md)

---

## Quick start

```bash
node build.mjs                 # builds to dist/ (Node 20+; no npm install needed)
node scripts/serve.mjs 8080    # preview at http://localhost:8080
```

The build fails on any of the following:

- a broken internal link or asset
- a missing `#anchor`
- a page without exactly one `<h1>`
- a duplicate `<title>`

## Deploying to Netlify

| Setting | Value |
|---|---|
| Build command | `node build.mjs` (already set in `netlify.toml`) |
| Publish directory | `dist` (already set in `netlify.toml`) |
| Node version | 22 (set in `netlify.toml`) |
| **Required env var** | `SITE_URL` = final domain, e.g. `https://www.yourdomain.com` (no trailing slash) |
| Optional env vars | `GA4_MEASUREMENT_ID`, `GOOGLE_SITE_VERIFICATION` (see `.env.example`) |

### Steps

1. **Create the site.**
   - **Git:** in Netlify, choose Add new site → Import an existing project and connect this repository. The settings above are picked up automatically.
   - **ZIP / drag-and-drop:** run `node build.mjs` locally *with `SITE_URL` and `CONTEXT=production` set*, then drag the `dist/` folder onto Netlify → Sites → Deploy manually. Manual deploys skip the build step, so environment variables must be set when you build locally:

     ```bash
     CONTEXT=production SITE_URL=https://www.yourdomain.com node build.mjs
     ```

2. **Set environment variables.** In Site configuration → Environment variables, set `SITE_URL`. Without it, canonical URLs fall back to Netlify's own URL.
3. **Enable form detection.** In Forms → Enable form detection, turn detection on, then redeploy. The form is named `estimate`.
4. **Set up form notifications.** In Forms → Form notifications, add an email notification for the `estimate` form, sent to the business inbox.
5. **Connect the domain.** In Domain management → Add a domain, follow Netlify's DNS steps. HTTPS (Let's Encrypt) is issued automatically once DNS resolves.
6. **Submit a test estimate** on the live site and confirm both of these:
   - it appears under Forms
   - the notification email arrives

See section 14 of the QA report for the full post-launch checklist, including Search Console, GA4 and the sitemap.

### Non-production deploys

Deploy previews and branch deploys are built with:

- `noindex` on every page
- a `Disallow: /` robots.txt

Only the production context is indexable. The logic is in `site.config.mjs`.

## Project structure

```
build.mjs                 Static build + integrity checks + sitemap/robots/manifest
site.config.mjs           ← Business facts, services, service area, env handling (edit here)
netlify.toml              Build command, publish dir, Node version
src/
  lib/layout.mjs          <head>, header, footer, site-wide JSON-LD
  lib/components.mjs      picture(), estimate form, CTAs, FAQ, breadcrumbs, icons
  lib/service-template.mjs Shared structure for individual service pages
  pages/*.mjs             One module per page: path, title, description, body
  assets/css/main.css     Design system (tokens at the top)
  assets/js/main.js       Nav, mobile menu, form validation/submission, event tracking
  assets/js/analytics.js  GA4 loader (only included when GA4_MEASUREMENT_ID is set)
  assets/img/             Optimized images (generated, committed)
  data/images.json        Image manifest (generated)
  static/                 Copied to the site root: favicon.ico, _headers (CSP, HSTS, caching), _redirects
assets-src/               Original photos, logo and font (not deployed)
scripts/
  process-images.py       Regenerates all responsive images + brand assets
  subset-font.py          Regenerates the subset web font
  serve.mjs               Local preview server (pretty URLs, 404s, gzip)
qa/                       Playwright/axe/Lighthouse/html-validate tooling (not deployed)
docs/                     Research report, asset inventory
```

## Common edits

### Phone, owner or service area

Edit `site.config.mjs`. These values flow into every page, the footer and the structured data.

### Adding the business email

Set `business.email` in `site.config.mjs`. It then appears in the footer, the privacy policy and the JSON-LD.

### Page copy

Edit the matching file in `src/pages/`. Service pages share their structure through `src/lib/service-template.mjs`.

### Adding a page

1. Create `src/pages/new-page.mjs`, exporting `{ path, title, description, breadcrumbs, body }`.
2. Add its name to `pageModules` in `build.mjs`.

The page then joins the sitemap automatically.

### Replacing photos

1. Put the originals (at least 2000 px wide) in `assets-src/photos/`.
2. Add each one to `PHOTOS` in `scripts/process-images.py`.
3. Run the script (it needs Pillow 11+ with AVIF support):

   ```bash
   python3 scripts/process-images.py
   ```

4. Reference the photo with `picture('file-name', { alt: '…', sizes: '…' })`.

## Running QA locally

```bash
node build.mjs && node scripts/serve.mjs 8080 &
cd qa && npm ci
node test.mjs              # 8 viewports, axe WCAG 2.2 AA, menus, form flow, SEO, CSP, 404
npx html-validate --config .htmlvalidate.json "../dist/**/*.html"
node schema-check.mjs      # JSON-LD vs schema.org vocabulary (needs vendor/schemaorg.jsonld)
CHROME_PATH=/path/to/chrome node lighthouse.mjs
```

`schema-check.mjs` reads `vendor/schemaorg.jsonld`, which you download from https://schema.org/version/latest/schemaorg-current-https.jsonld.

## Analytics events

These events go to `dataLayer` in gtag format and reach GA4 when `GA4_MEASUREMENT_ID` is set:

| Event | When |
|---|---|
| `generate_lead` | Once per successful estimate submission. Fired on `/thank-you/`, and only when arriving from a submission, so reloads don't count. |
| `form_start` | First interaction with the estimate form |
| `click_call` | Any `tel:` link click |
| `click_email` | Any `mailto:` link click (once an email is configured) |

**Mark `generate_lead` as a key event in GA4.**
